ConfirmDialog

Overview

The "are you sure?" dialog, and the single-value prompt. Built on [Modal](/docs/display/modal), so scroll-lock, focus, Escape and backdrop dismissal are already handled — this only owns the copy, the two buttons and the promise.

Why a promise and not an event

The obvious alternative is a global confirm:request event plus callbacks. With that, every call site has to juggle two async channels plus a "did this already fire?" flag, and a caller that returns early leaves the event unfired.

With a promise the control flow is linear and cannot get wrong:

API

  • ask(options) -> Promise<boolean> — true confirmed, false cancelled or dismissed.
  • prompt(options) -> Promise<string|null> — the value, or null if cancelled.
  • isOpen (boolean) — whether a question is currently on screen.

Options for both (all optional):

Defaults can be set once on the component (confirmLabel, cancelLabel, confirmVariant props) and overridden per call.

The one invariant

Every ask()/prompt() resolves exactly once. A dialog that could be dismissed without settling would leave the awaiting caller hanging for the life of the page, so Escape, the backdrop, the X button, a second question arriving while one is open, and destroying the component all resolve — as cancellations. There is a spec for each of those.

Best Practices

Put the consequence in message, not in the title. The title says what is being asked; the message says what happens if the answer is yes. "This cannot be undone" is worth more than "Confirm".
Use danger: true for anything irreversible. It is the only thing that distinguishes "shall I publish this?" from "shall I delete this?", and it is one property.

Pitfalls

required blocks the confirm button and paints an error, but it does not disable it. That is deliberate: a permanently greyed-out button tells the user nothing about why. If the empty case should not even be reachable, validate before opening the dialog.

A prompt's field is focused when it opens, so Enter confirms. If the answer is not something a user should be able to submit with a single keystroke, do not put a prompt on that action.

ask() cannot prevent the dialog from being dismissed — Escape and the backdrop always count as "no". If the answer must be explicit, do not make it cancellable: leave dismissable on and accept that a stray Escape reads as a refusal.

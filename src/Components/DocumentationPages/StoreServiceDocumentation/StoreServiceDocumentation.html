StoreService

Overview

A small facade over slice.context. It exists so context persistence is configured in one place instead of every state-owning service repeating create(name, initial, { persist: true, ... }).

Build it first in your composition root, then recover it anywhere with slice.getComponent('StoreService').

API

  • ensure(name, initialState, storageKey) — create the context only if it does not exist. Idempotent.
  • has(name) / get(name)
  • set(name, updater) — updater is (prev) => next, the same contract as slice.context.setState.
  • watch(name, component, callback, selector) — subscribe a component to a slice of state.

Watchers registered with a component are cleaned up automatically when it is destroyed — do not unwatch by hand. selector narrows the callback, so the watcher only fires when the relevant part changes rather than on every write.

Prop Scenarios

Best Practices

One context per domain concept, not per screen: a settings context everyone reads beats three copies of the same preferences that can drift apart.

Pitfalls

ensure is create-if-absent, not a migration helper. Adding a key to a context's initialState after release does not backfill it for a returning user — their stored copy is already there. Shape migrations belong in the service that owns that state, in its own init().

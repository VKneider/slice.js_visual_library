Chip

Overview

A Chip is a compact label for a filter, a tag, or a selected value in a multi-select. It sits inline, wraps long text with an ellipsis, and can carry an icon and a remove affordance.

For a read-only status pill, use Badge instead — a Badge carries state, a Chip carries a selection you can act on.

API

  • label (string)
  • icon (string) — an Icon name; empty renders no glyph
  • variant (neutral | accent | success | warning | danger, default neutral)
  • size (sm | md, default md)
  • disabled (boolean)
  • removable (boolean) — renders a real <button> remove affordance
  • removeLabel (string, default "Remove") — used for the button's aria-label and tooltip
  • onRemove (function) — called with the chip's label

The remove button is labelled "<removeLabel>: <label>", so a screen-reader user hears *which* chip they are removing rather than a list of identical "Remove" buttons.

Prop Scenarios

Best Practices

Use Chip for things the user chose and can remove, Badge for things the system decided. Mixing the two makes it unclear whether a pill is clickable.

Pitfalls

A Chip is not draggable. To reorder a list of chips, register them with DragDropService yourself — sorting is a container concern, not something a chip should own.

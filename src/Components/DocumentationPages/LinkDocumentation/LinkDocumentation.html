Link

Overview

Link is a route-aware <a>: it keeps a real href in the DOM (so right-click → open in new tab still works, and the URL is visible on hover) but intercepts the click and hands the path to slice.router.navigate, so navigation goes through the client-side router instead of a full page load.

It is built with DOM APIs (setAttribute / textContent) rather than an innerHTML template, so a path like javascript:... or text containing markup can never inject into the page.

API and Behavior

  • path — the route to navigate to. Also the anchor's href. Defaults to '#'.
  • text — the link label.
  • classes — extra class names applied to the <a>.
  • icon — an Icon name rendered before the label, aria-hidden (the label is the accessible name).
  • iconSize / iconColor — passed through to the Icon.
  • sub — a secondary line under the label (a count, a description).

The anchor is an inline flex row with a gap, text-decoration: none and color: inherit, so a link reads as part of its layout instead of fighting the UA's default link styling. Pass classes to add your own hover/underline treatment.

Prop Scenarios

Best Practices

Use Link for in-app navigation. For external destinations use a plain <a> with target / rel — routing an off-site URL through the router buys nothing.

Pitfalls

Link has no template and no setComponentProps: its props are read once, in the constructor, from whoever built the element. Changing them later means calling render() again — it is not a reactive component like Button or Tabs.

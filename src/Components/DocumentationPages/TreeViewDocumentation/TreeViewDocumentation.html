TreeView

Overview

TreeView renders a nested tree structure using TreeItem nodes. Each item can contain child items, and items with children include a collapsible caret. Supports click callbacks and path-based navigation.

API and Behavior

  • items (array of objects) defines the tree hierarchy.
  • Each item accepts: value (label), path (for navigation), items (child array), onClickCallback.
  • expanded — 'none' (default) or 'all'. See below; this one matters.
  • onClickCallback is propagated to all child TreeItem nodes.
  • TreeView uses TreeItem internally via slice.build('TreeItem', ...).
  • Collapse state is persisted to localStorage.

Everything starts closed by default

A branch is collapsed until something opens it, and there are only two things that do: the caret, and activePath auto-opening the ancestors of the current page. Hand a TreeView nested items that carry a path and no activePath, and you get three flat rows, 79–119px of blank space where the children should be, and a label that does nothing when clicked — because the label's toggle is only wired for branches *without* a path:

That is the right default for a nav sidebar, which should show the current page rather than the whole site. It is the wrong default for a tree you want to read, so ask for it:

TreeItem.setExpanded(open) is public too, for opening one branch yourself. activePath and expanded: 'all' compose: expanded is applied last and wins.

Item aliases

text/label are accepted for value, and children for items. The children alias exists because it is what nearly every other tree library calls it, and the cost of *not* accepting it was severe: children is a getter-only property on HTMLElement, so spreading an item that carried one made the props assignment throw Cannot set property children, the item was never created, and every branch of the tree disappeared — with one ERROR in a console you are not watching and nothing at all on screen.

Only the keys TreeItem declares are forwarded to it, so no data shape can clobber a native DOM property the same way.

Prop Scenarios

Best Practices

Use path on items that should navigate. Items without path toggle their children on click instead.

Pitfalls

TreeItem uses localStorage to persist open/closed state. State persists across sessions for items with the same label.
How a branch opens depends on whether it has a path. A branch with one toggles only from its caret — clicking the label is left free for navigation. A branch without one toggles from the caret *or* the label, so it works with no caret affordance expected. Drop the path from a branch you always want collapsible.
A branch collapses by animating .container from scrollHeight to 0, then leaving height: auto. A branch that is *route*-opened goes straight to height: auto, so it will not animate — that is deliberate, since a fixed pixel height clips descendants that expand later.

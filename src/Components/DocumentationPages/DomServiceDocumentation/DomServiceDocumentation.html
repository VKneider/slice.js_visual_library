DomService

Overview

DomService.reconcile() is the canonical way to render a variable-length list of child components. Give it your data and a stable key per item; it keeps the DOM, the component registry and the destroy lifecycle in sync.

Why it exists

The two obvious alternatives are both broken, in ways that only show up as a slow memory leak:

  • container.innerHTML = '' removes nodes without running beforeDestroy(). Every child's

document/window listeners, timers and registry entry survive. The framework never gets to clean up.

  • Re-creating a node (rather than moving it) re-runs its constructor and does the same thing.

So reconcile does three things, in this order:

  1. Refresh in place. For each item, find the existing node by its stable sliceId and update it.

Only a genuinely new item is built.

  1. Prune. Every child whose data is gone is destroyed with slice.controller.destroyComponent,

which runs beforeDestroy(). This happens before reordering so a dead node is never a reorder target.

  1. Enforce order. The DOM is moved to match items. insertBefore moves a node, it does not

clone it, so no constructor re-runs — and only nodes that are actually out of place move.

API

  • keyOf(item) — the identity used across renders. Derive it from a stable id, never from the

array index: an index key makes item 1 keep its component (and its state) when it becomes item 2.

  • props(item) — the props for one item.
  • refresh(node, props) — replaces the default slice.setComponentProps(node, props). Use it when

props are interdependent, or when the child builds sub-components asynchronously and needs its own update() in a specific order.

dom.destroyChildren(container) tears down every registered child at once.

Prop Scenarios

Best Practices

Call reconcile after every change to the data — a push, a filter, a re-sort — and nowhere else. If two places reconcile the same container, they will fight over the order.

Pitfalls

Do not use the array index as keyOf. With an index key, inserting at the front makes item 1 inherit item 0's component — and its scroll position, its open/closed state, and its focus.
reconcile only manages direct children that carry a slice-id. Anything you append by hand inside the container is left alone; wrap it if it should be reconciled with the data.

DragDropService

DragDropService is a singleton Service that provides headless drag-and-drop and resize capabilities using pointer events. It handles ghost elements, axis constraints, drop target hit-testing, and resize handles without any visual dependency.

Getting the instance

Because it is a singleton, build it once (anywhere) and recover the same instance elsewhere with slice.getComponent('DragDropService') — no need to thread a reference around.

This component ships TWO files, and slice get only delivers one. ``bash slice get DragDropService ls src/Components/Service/DragDropService/ # expect DragDropService.js AND dndGeometry.js ` DragDropService.js imports ./dndGeometry.js, a sibling module holding the resize maths. The CLI follows imports between *registered components*, but a bare ./relative.js inside a component folder is not fetched — the download fails silently and the service throws at runtime with dndGeometry is not defined. If it is missing after slice get, copy it from the registry repo. This is the only component in the library with a sibling module, and the reason is deliberate: the geometry maths was split out so it could be tested in plain Node (DragDropService.test.js runs under node --test`, with no browser).

Draggable

Make an element follow the pointer with a semi-transparent ghost.

Drag with axis constraint

Restrict movement to a single axis.

Droppable

Register drop targets and react when a draggable is dropped on them.

Resizable

Add resize handles to any element. The element needs position: relative (applied automatically).

Combined: Draggable + Resizable

A panel that is draggable by its header and resizable by its edges.

Free positioning

Elements stay where they are dropped. The service sets position: fixed and applies the final coordinates automatically.

Sortable

Reorder items inside a container by dragging them.

onReorder fires only when the order actually changed. A gesture the browser interrupts with pointercancel puts the item back where it started and reports nothing.

Touch support

Drag-and-drop works on touch devices without any extra wiring.

A finger on a draggable is ambiguous — scroll or drag? — and the browser settles it at the first move: unless touch-action forbids panning, it starts scrolling and fires pointercancel, after which no pointermove/pointerup ever arrives for that pointer. DragDropService handles this in two ways:

1. Hold-to-arm. A touch drag does not begin at pointerdown. The finger has to stay put for touchDelay ms (200 by default) first. Moving more than 8 px during that hold means "scroll", so the service cancels and hands the gesture back to the page. Once armed, a non-passive touchmove listener calls preventDefault() — the only way to stop the browser panning mid-drag — and the long-press context menu and iOS selection callout are suppressed. Mouse and pen are unaffected: they start immediately.

2. pointercancel cleans up. When the browser takes the gesture anyway (a scroll, an incoming call, a system gesture), the drag ends *cancelled*, not dropped:

Without this the service wedged permanently: _activeDrag stayed set, so every later drag was refused, and a sortable left its item display: none with the ghost stuck on screen.

Auto-scroll chains across scrollers

Holding a pointer near an edge scrolls the nearest scrollable ancestor — and when that reaches its end, the next ancestor takes over, ending at the page. This matters on a phone, where a drag out of a nested sidebar (a list, a card column) would otherwise only ever scroll that sidebar, leaving every drop target out of reach. The target is re-picked on every animation frame, so a finger held still at the edge still hands over.

Cleanup

As an app-lifetime singleton, its global listeners, ghost, and registrations are cleaned up automatically by the framework (beforeDestroy) when the service is torn down — you don't tear it down by hand.

Best Practices

  • Set touch-action: none on draggable elements (already set on resize handles). **It does not

disable scrolling by itself** — the hold-to-arm delay is what keeps a tap-scrollable list scrollable while a deliberate hold starts a drag.

  • Use handle when elements should be draggable only from a specific child (e.g., a header).
  • Always call detach(node) when removing a registered element from the DOM.
  • Use accept on droppables to filter which draggables are accepted.
  • Auto-scroll is on by default: dragging near an edge scrolls the nearest scrollable ancestor that

can still move that way, handing over to the next one — and finally the page — as each is exhausted. Pass autoScroll: false to a draggable or sortable to opt out.

  • Auto-scroll only runs when the drag has somewhere to go (freePosition or at least one

droppable). A ghost-only drag with no droppables never scrolls the page.

  • Sortables ignore presses that land on an interactive descendant (button, input, select,

textarea, a, [contenteditable], [data-act], and the Slice form controls), so a button inside a sortable card still works.
